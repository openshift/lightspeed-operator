# Bundle Composition

The `lightspeed-operator` package has **one unified Classic + Agentic OLM bundle** per release. Its single CSV installs both controllers, the Classic and Agentic CRDs/RBAC, webhook resources, and the full related-image set on supported OCP 4.x and 5.x versions. After the FBC cutover, each supported per-OCP-version catalog must reference the same unified bundle digest; OCP version selects runtime capability, not a new bundle variant. Older catalog history may still contain Classic-only releases. This supersedes the OLS-3899 v1/v2 split. See [decision 0002](../decisions/0002-unified-bundle-runtime-gating.md) and [FBC release process](../how/fbc-release.md).

## Behavioral Rules

### Bundle Structure and Delivery

1. `bundle/` and `bundle.Dockerfile` are the single bundle source. `make bundle` / `hack/update_bundle.sh -i related_images.json [-v VERSION]` generate one CSV, one set of manifests, and a compatibility annotation covering supported OCP versions (currently `>=v4.16`). No v1/v2 selector, CSV template split, or separate `ols-bundle-v2` release Application is part of the target design.
2. The CSV contains deployments for `lightspeed-operator-controller-manager` and `lightspeed-agentic-operator-controller-manager`, their required static permissions and webhook resources, and the Classic and Agentic API surface. Both controller processes start on bundle installation even on OCP 4.x; installation alone MUST NOT activate Agentic workloads.
3. Per-OCP-version FBC catalogs remain. [PLANNED: OLS-4352] Each supported catalog must reference the **same released unified bundle digest**, and its compatibility metadata and catalog content must be validated before publication. The former Classic-only v1 bundle remains a migration source until cross-version validation and retirement are approved; do not infer safe downgrade from a successful bundle build.

### CRD Ownership

4. `agentic.openshift.io` CRD YAML and agentic static RBAC are generated by `lightspeed-agentic-operator`, not authored in this repository.
5. The pinned agentic-operator ref and `make sync-agentic-crds` supply the CRDs/RBAC shipped in the unified bundle. When the agentic API or static permissions change, update the ref and sync; do not hand-edit the generated manifests. Per-run sandbox RBAC is created at runtime by the agentic controller and is not bundle RBAC.

### Image References

6. Both controller images are specified in their respective CSV deployments. Their operand images are configured via controller startup flags or environment variables.
7. `related_images.json` is the single image input to `hack/update_bundle.sh`. The unified CSV's `spec.relatedImages` includes the Classic and Agentic images for disconnected installs, regardless of OCP version. The script substitutes image digests into deployments and args; `operator_arg` names Classic controller flags. There is no per-variant `bundles` filter.
8. The lightspeed-operator owns the chat and agentic console plugin operands and the opt-in alerts adapter; the agentic controller must not deploy a duplicate agentic console plugin. The agentic console and alerts adapter are subject to the runtime gate below, not to OLM catalog selection.

### Runtime Boundary

9. The controllers reconcile different API groups (`ols.openshift.io` and `agentic.openshift.io`) and share no controller state. The Classic operator publishes the `lightspeed-agentic-configuration` handoff ConfigMap and client CA Secret names for the agentic runtime; it does not reconcile AgenticRun objects. Classic `MCPServer` and `ToolFiltering` switches do not start the agentic controller.
10. Normal Classic reconciliation reads one `ClusterVersion/version` snapshot. The Agentic gate is **Enabled** only if the latest update is `Completed`, matches `status.desired.version`, and the completed OCP major version is at least 5; **Disabled** for the same matching completed state on OCP 4.x; **Unknown** if the resource is unreadable, absent, incomplete, mismatched, or unparseable. Desired version alone does not establish that an upgrade has completed.
11. Under Disabled or Unknown, Classic MUST NOT create, modify, or remove agentic operands or agentic client CA Secrets during normal reconciliation. Disabled may report `UnsupportedOCPVersion`; Unknown must preserve existing Agentic status and retry without claiming an unsupported version. Explicit OLSConfig deletion runs finalizer cleanup before version gating. When Enabled, reconciliation and explicit opt-out cleanup may proceed according to component configuration. An Enabled Classic-side gate permits configured operands (including the console) and the handoff without checking for `AgenticOLSConfig`. Agentic workflow execution requires an explicit, unsuspended `AgenticOLSConfig` and [PLANNED: OLS-4350] validation of the agentic-controller version gate before release cutover. Bundle installation or a Classic-side gate alone is not workflow opt-in. See [decision 0002](../decisions/0002-unified-bundle-runtime-gating.md).

## Configuration Surface

| Item | Location | Description |
| --- | --- | --- |
| Agentic CRD/RBAC pinned ref | Makefile / sync target | Source revision for generated Agentic static APIs and RBAC |
| Controller images | Unified CSV deployment specs | Classic and Agentic controller images |
| Agentic controller `--sandbox-mode` | Unified CSV deployment args | `bare-pod` (default) or `sandbox-claim` |
| Classic `--agentic-sandbox-image` | `cmd/main.go`, `related_images.json` | Sandbox image in the handoff PodSpec |
| Classic `--rhokp-image` | `cmd/main.go`, `related_images.json` | RHOKP image |
| Classic `--alerts-adapter-image` / `--agentic-console-image` | `cmd/main.go`, `related_images.json` | Optional agentic operand images |

## Constraints

1. The Classic controller does not import or reconcile `agentic.openshift.io` API types.
2. The two controllers and their operands must support disconnected installs: include required images in the unified bundle and allow image overrides.
3. Static Agentic RBAC and CRDs ship even on OCP 4.x. Runtime gating, not CRD absence, protects unsupported clusters. A known 4.x version does not establish a supported downgrade path from 5.x.
